## plugin.json 스키마

### 필수 필드

```json
{
  "name": "string (필수, kebab-case)",
  "description": "string (필수)",
  "version": "string (필수, semver)",
  "author": {
    "name": "string (필수)",
    "email": "string (필수)"
  }
}
```

### 전체 스키마

```typescript
interface PluginJson {
  name: string;              // 플러그인 식별자 (kebab-case)
  description: string;       // 플러그인 설명
  version: string;           // 버전 (semver: "1.0.0")
  author: {
    name: string;           // 작성자 이름
    email: string;          // 작성자 이메일
  };
}
```

### 예제

```json
{
  "name": "my-awesome-plugin",
  "description": "A plugin that does awesome things",
  "version": "1.0.0",
  "author": {
    "name": "John Doe",
    "email": "john@example.com"
  }
}
```

## Commands 파일 형식

### 파일 위치
`commands/*.md`

### Frontmatter 스키마

```yaml
---
description: string (필수)           # 명령어 설명
argument-hint: string (선택)         # 인자 힌트
allowed-tools: string (선택)         # 허용된 도구
---
```

### Frontmatter 필드 설명

#### description (필수)
```yaml
description: Create a git commit
```

#### argument-hint (선택)
```yaml
argument-hint: feature name
```
- 명령어 인자에 대한 힌트
- UI에 표시됨

#### allowed-tools (선택)
```yaml
allowed-tools: Bash(git:*), Read, Write
```

**형식**:
- `ToolName`: 도구의 모든 사용 허용
- `ToolName(pattern)`: 특정 패턴만 허용
- `,`로 여러 도구 구분

**예제**:
```yaml
# Git 명령어만 허용
allowed-tools: Bash(git:*)

# Git과 npm 명령어 허용
allowed-tools: Bash(git:*), Bash(npm:*)

# 파일 읽기와 쓰기만 허용
allowed-tools: Read, Write, Edit

# 모든 도구 허용 (기본값)
# allowed-tools 필드 생략
```

### 특수 변수

#### $ARGUMENTS
사용자가 입력한 인자로 자동 치환됩니다.

```markdown
명령어: /create-feature user authentication
파일에서: Create feature: $ARGUMENTS
실제 값: Create feature: user authentication
```

#### !`명령어`
실행 시점에 명령어를 실행하고 결과를 삽입합니다.

```markdown
Current branch: !`git branch --show-current`
```

실제 실행 시:
```markdown
Current branch: main
```

### 전체 예제

```markdown
---
description: Create a feature branch
argument-hint: feature name
allowed-tools: Bash(git:*)
---

## Context

- Current branch: !`git branch --show-current`
- Recent branches: !`git branch -a | head -10`

## Your task

Create a new feature branch named: feature/$ARGUMENTS

Steps:
1. Check if branch exists
2. Create from current branch
3. Switch to new branch
4. Confirm to user
```

## Agents 파일 형식

### 파일 위치
`agents/*.md`

### Frontmatter 스키마

```yaml
---
name: string (필수)                  # 에이전트 식별자
description: string (필수)           # 에이전트 설명
tools: string (필수)                 # 사용 가능한 도구
model: string (선택)                 # AI 모델
color: string (선택)                 # UI 색상
---
```

### Frontmatter 필드 설명

#### name (필수)
```yaml
name: code-explorer
```
- 에이전트 고유 식별자
- kebab-case 권장

#### description (필수)
```yaml
description: Deeply analyzes existing codebase features
```
- 에이전트가 하는 일에 대한 설명

#### tools (필수)
```yaml
tools: Glob, Grep, Read, Write
```

**사용 가능한 도구**:
- `Glob`: 파일 패턴 검색
- `Grep`: 코드 내용 검색
- `Read`: 파일 읽기
- `Write`: 파일 쓰기
- `Edit`: 파일 편집
- `Bash`: 셸 명령어 실행
- `WebSearch`: 웹 검색
- `WebFetch`: 웹 페이지 가져오기
- `TodoWrite`: TODO 목록 관리
- `Task`: 하위 에이전트 실행
- `*`: 모든 도구 (비권장)

**와일드카드 + 제외**:
```yaml
# 모든 도구 허용
tools: *

# Write 제외한 모든 도구
tools: *, !Write

# Bash 제외한 모든 도구
tools: *, !Bash
```

#### model (선택)
```yaml
model: sonnet
```

**모델 종류**:
- `opus`: 가장 강력, 느림, 비쌈
- `sonnet`: 균형잡힌 선택 (기본값)
- `haiku`: 빠르고 저렴, 간단한 작업용

**선택 가이드**:
- 복잡한 분석, 아키텍처 설계: `opus`
- 일반적인 작업: `sonnet`
- 간단한 검색, 포맷팅: `haiku`

#### color (선택)
```yaml
color: yellow
```

**색상 종류**:
- `red`
- `yellow`
- `green`
- `blue`
- `purple`

### 전체 예제

```markdown
---
name: performance-analyzer
description: Analyzes code for performance bottlenecks
tools: Glob, Grep, Read, WebSearch
model: sonnet
color: red
---

You are a performance analysis expert.

## Your Mission

Analyze the codebase for performance issues and provide
actionable recommendations.

## Analysis Areas

1. Algorithm Complexity
2. Memory Usage
3. I/O Operations
4. Database Queries

## Output Format

For each issue:
- **Location**: file:line
- **Issue**: Description
- **Impact**: High/Medium/Low
- **Fix**: Suggested solution
```

## Hooks 설정 형식

### 파일 위치
`hooks/hooks.json`

### 스키마

```typescript
interface HooksJson {
  description: string;        // Hook 설명
  hooks: {
    SessionStart?: HookConfig[];
    PreToolUse?: HookConfig[];
    PostToolUse?: HookConfig[];
  };
}

interface HookConfig {
  hooks: HookCommand[];
  matcher?: string;           // PreToolUse/PostToolUse만
}

interface HookCommand {
  type: "command";
  command: string;
}
```

### Hook 타입

#### SessionStart
세션 시작 시 한 번 실행

```json
{
  "description": "Session start hook",
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PLUGIN_ROOT}/hooks-handlers/init.sh"
          }
        ]
      }
    ]
  }
}
```

#### PreToolUse
도구 사용 전 실행

```json
{
  "description": "Pre-tool hook",
  "hooks": {
    "PreToolUse": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "python3 ${CLAUDE_PLUGIN_ROOT}/hooks/check.py"
          }
        ],
        "matcher": "Edit|Write|MultiEdit"
      }
    ]
  }
}
```

**matcher**: 정규표현식으로 도구 이름 매칭
- `Edit`: Edit 도구만
- `Write`: Write 도구만
- `Edit|Write`: Edit 또는 Write
- `Edit|Write|MultiEdit`: 여러 도구

#### PostToolUse
도구 사용 후 실행

```json
{
  "description": "Post-tool hook",
  "hooks": {
    "PostToolUse": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PLUGIN_ROOT}/hooks-handlers/notify.sh"
          }
        ],
        "matcher": "Write|Edit"
      }
    ]
  }
}
```

### 여러 Hook 정의

```json
{
  "description": "Multiple hooks",
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PLUGIN_ROOT}/hooks-handlers/init.sh"
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PLUGIN_ROOT}/hooks/security-check.py"
          }
        ],
        "matcher": "Edit|Write"
      },
      {
        "hooks": [
          {
            "type": "command",
            "command": "${CLAUDE_PLUGIN_ROOT}/hooks/format-check.sh"
          }
        ],
        "matcher": "Write"
      }
    ]
  }
}
```

## Hook 입력/출력 형식

### PreToolUse / PostToolUse 입력 형식

Hook 스크립트는 stdin으로 JSON 데이터를 받습니다.

```typescript
interface HookInput {
  session_id: string;         // 세션 ID
  tool_name: string;          // 도구 이름
  tool_input: any;            // 도구 입력 (도구마다 다름)
}
```

### 도구별 입력 형식

#### Write 도구
```json
{
  "session_id": "abc123",
  "tool_name": "Write",
  "tool_input": {
    "file_path": "/path/to/file.ts",
    "content": "file content here..."
  }
}
```

#### Edit 도구
```json
{
  "session_id": "abc123",
  "tool_name": "Edit",
  "tool_input": {
    "file_path": "/path/to/file.ts",
    "old_string": "old content",
    "new_string": "new content"
  }
}
```

#### Read 도구
```json
{
  "session_id": "abc123",
  "tool_name": "Read",
  "tool_input": {
    "file_path": "/path/to/file.ts"
  }
}
```

#### Bash 도구
```json
{
  "session_id": "abc123",
  "tool_name": "Bash",
  "tool_input": {
    "command": "git status"
  }
}
```

### JSON 파싱 예제

#### Python
```python
import json
import sys

input_data = json.loads(sys.stdin.read())
session_id = input_data.get("session_id")
tool_name = input_data.get("tool_name")
tool_input = input_data.get("tool_input", {})
file_path = tool_input.get("file_path", "")
```

#### Bash (jq 사용)
```bash
INPUT=$(cat)
TOOL_NAME=$(echo "$INPUT" | jq -r '.tool_name')
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')
CONTENT=$(echo "$INPUT" | jq -r '.tool_input.content // empty')
```

### Hook 출력 형식

#### PreToolUse / PostToolUse

**표준 출력 (stdout)**: 무시됨

**표준 에러 (stderr)**: 사용자에게 표시됨
```bash
echo "⚠️  Warning: Something to note" >&2
```

**종료 코드**:
- `0`: 도구 실행 허용 (또는 계속 진행)
- `2`: 도구 실행 차단 (PreToolUse만)
- 기타: 에러

#### SessionStart

**출력**: JSON to stdout

```bash
cat << 'EOF'
{
  "hookSpecificOutput": {
    "hookEventName": "SessionStart",
    "additionalContext": "Additional context for AI..."
  }
}
EOF
```

**구조**:
```typescript
interface SessionStartOutput {
  hookSpecificOutput: {
    hookEventName: "SessionStart";
    additionalContext: string;  // AI 프롬프트에 추가될 텍스트
  };
}
```

### 전체 Hook 예제

#### PreToolUse Hook (Python)

```python
#!/usr/bin/env python3
import json
import sys

def main():
    try:
        # Read input
        input_data = json.loads(sys.stdin.read())

        # Extract data
        tool_name = input_data.get("tool_name")
        tool_input = input_data.get("tool_input", {})
        file_path = tool_input.get("file_path", "")

        # Check condition
        if not file_path.endswith(".ts"):
            sys.exit(0)  # Allow - not TypeScript

        # Perform check
        content = tool_input.get("content") or tool_input.get("new_string", "")

        if "any" in content:
            print("⚠️  Warning: Using 'any' type reduces type safety", file=sys.stderr)
            sys.exit(2)  # Block

        sys.exit(0)  # Allow

    except Exception as e:
        print(f"Hook error: {e}", file=sys.stderr)
        sys.exit(0)  # Allow on error

if __name__ == "__main__":
    main()
```

#### SessionStart Hook (Bash)

```bash
#!/bin/bash

cat << 'EOF'
{
  "hookSpecificOutput": {
    "hookEventName": "SessionStart",
    "additionalContext": "You are in strict mode.\n\nRules:\n1. Always write tests\n2. Follow TypeScript strict mode\n3. Document public APIs\n\nRemind users of these rules when relevant."
  }
}
EOF

exit 0
```

#### PostToolUse Hook (Bash)

```bash
#!/bin/bash

INPUT=$(cat)
TOOL_NAME=$(echo "$INPUT" | jq -r '.tool_name')
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')

# Only process TypeScript files
if [[ ! "$FILE_PATH" =~ \.ts$ ]]; then
  exit 0
fi

# Run linter
if command -v eslint &> /dev/null; then
  if ! eslint "$FILE_PATH" 2>&1 >/dev/null; then
    echo "⚠️  ESLint found issues in $FILE_PATH" >&2
    echo "Run: eslint --fix $FILE_PATH" >&2
  fi
fi

exit 0
```

- [ ] 플러그인 디렉토리 생성
- [ ] `.claude-plugin/plugin.json` 작성
- [ ] `README.md` 작성
- [ ] Commands: `commands/*.md` 작성
- [ ] Agents: `agents/*.md` 작성
- [ ] Hooks: `hooks/hooks.json` 작성
- [ ] Hook handlers: `hooks-handlers/*` 작성
- [ ] 마켓플레이스에 등록

### Commands 파일 체크리스트

- [ ] Frontmatter에 `description` 필수
- [ ] `$ARGUMENTS` 사용 시 `argument-hint` 추가
- [ ] 도구 제한이 필요하면 `allowed-tools` 설정
- [ ] 동적 컨텍스트는 `!`명령어`` 사용
- [ ] 명확한 지시사항 작성

- [ ] Frontmatter에 `name`, `description`, `tools` 필수
- [ ] 적절한 `model` 선택 (haiku/sonnet/opus)
- [ ] 필요한 도구만 `tools`에 나열
- [ ] 출력 형식 명시
- [ ] 파일:라인 형식으로 위치 명시

### Hooks 파일 체크리스트

- [ ] `hooks/hooks.json` 작성
- [ ] 적절한 Hook 타입 선택
- [ ] `matcher`로 도구 필터링 (PreToolUse/PostToolUse)
- [ ] Hook 스크립트 실행 권한 설정 (`chmod +x`)
- [ ] 에러 처리 구현
- [ ] stdin에서 JSON 읽기
- [ ] 적절한 exit 코드 반환
- [ ] 경고는 stderr로 출력
